### Цель проекта
Построить модель, предсказывающую отток клиентов банка (`churn`), чтобы банк мог приоритизировать клиентов с высоким риском ухода и направлять им целевые предложения (скидки, персональные условия) — вместо того, чтобы обращаться ко всем клиентам без разбора.

**Задача** : 
бинарная классификация (churn: 1 = ушёл, 0 = остался).

**Данные:**  набор данных банковского оттока клиентов с Kaggle.
10 000 клиентов банка, признаки — кредитный рейтинг, страна, пол, возраст, стаж обслуживания, баланс, количество продуктов, наличие кредитной карты, статус активности, предполагаемая зарплата. Дисбаланс классов: ~80% / ~20%.

### Метрика успеха:
Основная — `F1-мера` 

Дополнительная — `ROC-AUC / PR-AUC`

**Scope v1:**
- Обучение на всех доступных данных без дополнительной фильтрации по клиентам
- Сравнение моделей от простых к сложным: логистическая регрессия → SVM → случайный лес → бустинг
- Интерпретация через SHAP — **отложена** на следующую итерацию
- Деплой (FastAPI + Docker) — **отложен** на следующую итерацию

# Iteration 1

## Результаты

### Методология обучения и валидации

Данные разбиты на три части: **train (56%) / val (14%) / test (30%)** — стратифицированное
разбиение в два этапа (`train_test_split` со `stratify` дважды), чтобы сохранить
исходное соотношение классов (~80/20) в каждой части.

Гиперпараметры Random Forest и XGBoost подбирались через **Optuna** (50 итераций):
модели обучались на `train`, оценивались на `val` — `test` в процессе подбора не
участвовал. Для этого использован отдельный трансформер (`transformer_tuning`),
обученный (`fit`) только на `train`.

После выбора лучших гиперпараметров финальные модели (включая Logistic Regression и
SVM, без тюнинга) обучены на `train + val` вместе (`X_full_train`, 70% данных) с
помощью отдельного трансформера (`transformer_final`), обученного на этом же объёме.
`test` использовался только один раз — для финальной оценки, той же шкалой
(`transformer_final`), что и обучение.

### Сравнение моделей

| Модель | F1-score | ROC-AUC |
|---|---|---|
| Logistic Regression | 0.518 | 0.792 |
| SVM (RBF kernel) | 0.602 | 0.865 |
| **Random Forest** | **0.647** | 0.868 |
| XGBoost (тюнинг Optuna) | 0.632 | 0.868 |

Все модели обучены с учётом дисбаланса классов через `class_weight="balanced"`
(для XGBoost — `scale_pos_weight`). Метрики — на отложенном `test`, порог
классификации 0.5 (единый для всех моделей).

### Выбор финальной модели

**Random Forest** — лучший результат по основной метрике (F1). Изначально по
метрикам лидировал XGBoost, но при более честной схеме валидации (train/val/test
вместо прямого сравнения на test) и после расширения диапазона Optuna-поиска для
XGBoost (`max_depth` до 15) Random Forest стабильно показывает более высокий F1 при
сопоставимом ROC-AUC. Разница в ROC-AUC между RF и XGBoost (0.868 vs 0.868) в
пределах шума.

### Feature engineering

В пайплайн добавлены два признака (созданы до кодирования/масштабирования, отдельно
на каждом сыром куске данных — арифметика между колонками одной строки, утечки нет):
- `balance_per_product` — баланс, приходящийся на один продукт клиента
- `balance_per_tenure` — темп накопления баланса относительно стажа обслуживания
  (`balance / (tenure + 1)`)

Также протестирован бинарный признак `has_balance` (флаг наличия ненулевого
баланса) — эмпирически не дал прироста метрик и был исключён из финального
пайплайна.
